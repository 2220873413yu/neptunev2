# 核心业务流程

本文档不是完整业务说明，而是给二期需求定位用的流程索引。

## 用户登录与上下文

入口：

- `xms/neptune-app/src/main/java/com/xms/app/controller/UserInfoController.java`
- `xms/neptune-app/src/main/java/com/xms/app/service/impl/BizUserServiceImpl.java`
- `xms/neptune-app/src/main/java/com/xms/app/service/impl/AppTokenService.java`

关键点：

- App 多数业务接口通过 `SecurityUtils.getLoginAppUser()` 获取当前用户。
- Token header 是 `Authorization`。
- 用户关系、团队、等级相关逻辑集中在 `BizUserServiceImpl` 和 DAO 层 `UserInfoMapper.xml`、`UserRelationMapper.xml`。

二期改用户相关需求时，先确认：

- 是否影响注册/推荐关系。
- 是否影响团队层级查询。
- 是否影响等级配置和等级变更日志。
- 是否影响缓存键，如 `USER_PARENT_*`、`XMS_USER_LEVEL_MINING`。

## 提现流程

入口：

- App 查询提现配置：`GET /api/wal/walcg`
- App 发起提现：`POST /api/wal/awal`
- App 查询提现记录：`GET /api/wal/lwrd`
- 外部回调：`POST /api/withdrawal/callback`
- 后台管理：`/xms/withdrawal`、`/xms/withdrawalConfig`

核心代码：

- `BizWithdrawalController`
- `BizWithdrawalServiceImpl`
- `OpenController.withdrawalCallback`
- `WithdrawalController`
- `WithdrawalMapper.xml`
- `UserMoneyMapper.xml`
- `UserMoneyLogMapper.xml`

关键风险：

- 用户余额扣减和流水写入必须保持一致。
- 回调要检查幂等，避免重复到账或重复失败回滚。
- 提现配置、手续费、币种类型、状态枚举需要一起核对。
- Redis 锁常量中存在 `XMS_WITHDRAW_APPLY`、`XMS_WITHDRAW_CHECK`。

## 节点认购流程

入口：

- App 节点信息：`GET /api/np/nio`
- App 创建节点订单：`POST /api/np/cor`
- App 创建贡献/仓位订单：`POST /api/np/cpor`
- 外部回调：`POST /api/notify/nodeIdentity`
- 后台管理：`/xms/nodePlan`、`/xms/nodePlanOrder`

核心代码：

- `BizNodePlanController`
- `BizNodePlanServiceImpl`
- `OpenController.nodeIdentityCallback`
- `AsyncTaskServiceImpl.handelNodePlanOrder`
- `NodePlanMapper.xml`
- `NodePlanOrderMapper.xml`

关键风险：

- 创建订单后通常等待外部支付或链上回调。
- 回调需要处理订单状态、支付时间、收益释放参数。
- 定时任务会处理节点订单每日释放或收益逻辑。
- Redis 锁常量中存在 `XMS_BUY_NODE_PLAN`。

## 质押订单流程

入口：

- App 质押接口：`/api/stake`
- 外部质押回调：`POST /api/stakeOrder/callback`
- 购买积分回调：`POST /api/buyPointsCallback/callback`
- 后台管理：`/xms/stakeOrder`、`/xms/stakeRound`

核心代码：

- `BizStakeController`
- `BizStakeServiceImpl`
- `OpenController.stakeOrderCallback`
- `OpenController.buyPointsCallback`
- `AsyncTaskServiceImpl.handelStakeOrder*`
- `StakeOrderMapper.xml`
- `StakeRoundMapper.xml`
- `UserStakePositionMapper.xml`

关键风险：

- 质押订单状态、业务状态、链上 hash 和用户仓位要一致。
- 质押收益、日利率、财富仓解锁由定时任务和配置表共同影响。
- Redis 锁常量中存在 `XMS_STAKE_ORDER_PLAN`。

## 奖励与动态结算流程

入口：

- App 收益/奖励查询：`UserMoneyController`、`BizUserMoneyServiceImpl`
- 后台奖励记录：`/xms/rewardRecord`
- 后台每日统计：`/xms/rewardStatDay`
- Redis Stream 消费：`RedisStreamDynamicOrderSettlementReceiver`

核心代码：

- `AsyncDynamicOrderSettlementServiceImpl`
- `RedisStreamBizJobServiceImpl`
- `AsyncTaskServiceImpl`
- `RewardRecordMapper.xml`
- `RewardStatDayMapper.xml`
- `UserIncomeSummaryMapper.xml`

消息通道：

- `RedisConstant.StreamMsgConstant.ORDER_DYNAMIC_SETTLEMENT`
- `RedisConstant.StreamMsgConstant.XMS_DEAD_MSG`

关键风险：

- 奖励计算通常会同时影响用户余额、奖励记录、等级、团队业绩。
- Stream 消费失败会进入死信队列，需要 `dealRedisDeadMsg` 或后台补偿任务处理。
- 需要关注事务提交后发送消息的 `afterCommit` 逻辑。

## Canal 钱包流水监听

入口：

- 配置：`canal.filter: neptunev2.t_user_money`
- 生产消息：`CanalFLowRecordListener`
- 消费消息：`RedisStreamMsgFlowRecordReceiver*`

核心代码：

- `xms/neptune-admin/src/main/java/com/xms/web/core/config/canal`
- `xms/neptune-admin/src/main/java/com/xms/web/core/receiver`

关键风险：

- 当前 Canal 关注 `t_user_money`，通常用于钱包流水、资产快照或异步补偿。
- 修改钱包余额表时，要确认 Canal 流程是否依赖字段变化。
