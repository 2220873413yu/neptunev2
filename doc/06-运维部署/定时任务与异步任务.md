# 定时任务与异步任务

## Quartz 定时任务

模块：

- `xms/xms-quartz`

核心表：

- `sys_job`
- `sys_job_log`

管理接口：

- `SysJobController`：`/monitor/job`
- `SysJobLogController`：`/monitor/jobLog`

执行机制：

- `ScheduleUtils` 创建 Quartz Job。
- `JobInvokeUtil` 通过 `invokeTarget` 调用 Spring Bean 方法。
- 业务任务 Bean 是 `xmsTask`，源码在 `neptune-admin`。

## 业务任务 Bean

入口：

- `xms/neptune-admin/src/main/java/com/xms/web/task/XmsTask.java`

已开启方法：

- `dealSysLogs(Integer days)`：清理历史日志。
- `dealRedisDeadMsg()`：处理 Redis Stream 死信消息。
- `taskMsgCycle()`：处理事务消息阻塞。
- `handelNodePlanOrder()`：处理节点认购订单每日释放/收益。
- `handelStakeOrder()`：处理质押订单收益，任务类型 101。
- `handelStakeOrder102()`：每日释放保险仓利润，任务类型 102。
- `handelStakeOrder103()`：每日计算日质押日利率，任务类型 103。
- `handelStakeOrder104()`：财富仓收益解锁，任务类型 104。
- `handelStakeOrder105()`：补偿任务。

主要实现：

- `xms/neptune-admin/src/main/java/com/xms/web/service/impl/AsyncTaskServiceImpl.java`

高风险点：

- `AsyncTaskServiceImpl` 超过 3000 行，资金、收益、释放、补偿逻辑集中。
- 改需求前要先定位具体任务方法，不要全局改公共计算逻辑。
- 涉及金额、订单状态、奖励记录的任务要检查幂等表、状态字段和重复执行风险。

## Redis Stream

常量：

- `xms/xms-common/src/main/java/com/xms/common/constant/RedisConstant.java`

关键 Stream：

- `XMS_DEAD_MSG`：死信队列。
- `CANAL_MSG`：Canal 钱包流水相关消息。
- `ORDER_DYNAMIC_SETTLEMENT`：动态订单结算。
- `DELAY_DEL_CACHE`：延迟清缓存队列。
- `XMS_ASYNC_REWARD`：异步奖励队列，当前监听代码有注释痕迹。
- `DELAY_ORDER_TIMEOUT_QUEUE`：订单超时延迟队列。

基础设施：

- `xms/xms-common/src/main/java/com/xms/common/config/redis/stream`
- `RenegadeStreamTemplate`
- `DefaultXmsStreamTemplate`
- `XmsRedisStreamListener`
- `XmsStreamListenerDetector`

业务消费者：

- `RedisStreamDynamicOrderSettlementReceiver`
- `RedisStreamMsgFlowRecordReceiver`
- `RedisStreamMsgFlowRecordReceiverShard1`
- `RedisStreamMsgFlowRecordReceiverShard2`

业务处理：

- `RedisStreamBizJobServiceImpl`
- `AsyncDynamicOrderSettlementServiceImpl`

## Redisson 延迟队列

基础设施：

- `xms/xms-common/src/main/java/com/xms/common/config/redis/delayqueue`

关键入口：

- `RedissonTemplate`
- `RedissonInitQueueConfig`
- `RedissonDelayHandler`
- `RedissonDelayMsgReceiver`

业务配置：

- App 配置：`xms/neptune-app/src/main/java/com/xms/app/config/AppRedissonQueueConfig.java`
- 后台监听：`xms/neptune-admin/src/main/java/com/xms/web/core/receiver/DelayRedisQueueListener.java`

使用场景：

- `DELAY_ORDER_TIMEOUT_QUEUE`：订单超时处理。
- `DELAY_DEL_CACHE`：延迟清缓存。

## Canal

配置：

- `xms/neptune-admin/src/main/resources/application-dev.yml`
- `canal.destination: neptunev2`
- `canal.filter: neptunev2.t_user_money`
- `canal.mode: simpleDiy`

源码入口：

- `xms/neptune-admin/src/main/java/com/xms/web/core/config/canal`
- `CanalFLowRecordListener`
- `CanalMessageConsumer`

作用推断：

- 监听 `t_user_money` 变化。
- 将变更包装后发送到 Redis Stream `CANAL_MSG`。
- 后续由 `RedisStreamMsgFlowRecordReceiver*` 处理流水或补偿逻辑。

## 事务消息与补偿

相关源码：

- `AsyncTaskServiceImpl.taskMsgCycle`
- `AsyncTaskServiceImpl.dealRedisDeadMsg`
- `MqSendTemplate`
- `t_mq_transaction_log`

二期改动建议：

- 新增资金/奖励异步任务时，优先复用已有消息模板和幂等机制。
- 发送消息如果放在事务内，优先检查是否已有 `TransactionSynchronizationManager.afterCommit` 模式。
- 消费失败要明确是否进入 `XMS_DEAD_MSG`，以及是否已有补偿入口。
